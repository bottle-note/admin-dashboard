# 위스키 Excel 벌크 등록 Spec

## Summary

운영자가 위스키 Excel 양식을 내려받고, 작성한 파일의 오류와 중복 가능성을 확인한 뒤 오류가 없는 행을 한 번에 등록한다.

## Operator Goal

- 빈 Excel 양식을 내려받아 위스키 정보를 작성한다.
- 작성한 파일을 업로드해 어느 행을 고쳐야 하는지 확인한다.
- 수입 신고 화면에서 만든 등록 초안도 같은 양식에 값을 채운 뒤 이 화면에서 검증한다.

## Domain Model

- **양식**: 서버가 제공하는 고정 XLSX다. 시트, 헤더, 설명 행을 유지해야 한다.
- **검증**: 저장 없이 파일 구조와 각 행의 필수값·참조 ID·중복을 검사한다.
- **오류**: 해당 행은 등록할 수 없다. 예: 필수값 누락, 잘못된 지역·증류소·카테고리 ID, 파일 내부 중복.
- **경고**: 이미 등록된 위스키와 강하게 일치하는 후보가 있는 등 운영자 확인이 필요한 상태다.
- **정규화 행**: Excel 검증을 통과한 값을 서버가 저장 가능한 JSON 형태로 정리한 결과다.
- **일괄 등록**: 모든 행을 다시 검증한 뒤 하나의 트랜잭션으로 저장한다. 한 행이라도 오류가 있으면 0건 저장한다.

## API Contract

| 기능          | API                                                                | 현재 역할                                                          |
| ------------- | ------------------------------------------------------------------ | ------------------------------------------------------------------ |
| 양식 다운로드 | `GET /v1/alcohols/excel/template`                                  | XLSX 바이너리를 반환한다.                                          |
| 파일 검증     | `POST /v1/alcohols/excel/validate` (`multipart/form-data`, `file`) | 저장 없이 검증 결과와 행별 `clientRowId`, `normalized`를 반환한다. |
| JSON 검증     | `POST /v1/alcohols/bulk/validate`                                  | 최대 1,000행을 저장 없이 검증한다.                                 |
| 일괄 등록     | `POST /v1/alcohols/bulk`                                           | 전체 행을 재검증하고 오류가 없으면 모두 저장한다.                  |

검증 응답은 `totalRows`, `validRows`, `invalidRows`, `warningRows`와 행별 `rowNumber`, 이름·규격 정보, `errors`, `warnings`, 중복 후보 ID, 정규화 행을 제공한다. 검증 API는 빈 파일도 정상적으로 0건 결과로 반환할 수 있다.

등록 성공 응답은 `createdRows`, `rows(clientRowId, alcoholId)`, `validation`을 반환한다. 등록 직전 재검증이 실패하면 HTTP 400의 `errors`에 JSON 검증 결과와 같은 구조를 반환한다. 이때 화면은 `clientRowId`로 원래 Excel 행과 합쳐 기존 검증 결과 UI를 다시 사용한다. 반복 POST는 별도 등록이므로 자동 재시도하지 않는다.

## Screen Requirements

- 위스키 정보 관리 메뉴 아래에 `위스키 Excel 벌크 등록`을 추가한다. 기존 위스키 관리 화면과 같이 `ROOT_ADMIN`만 접근한다.
- 상단에는 `양식 다운로드`와 짧은 작성 안내를 둔다.
- 이어서 `.xlsx` 파일 선택 또는 드래그 영역과 `검증하기` 버튼을 둔다. 파일을 바꾸면 이전 검증 결과는 지운다.
- 검증이 끝나면 전체 행 / 오류 없는 행 / 오류 행 / 경고 포함 행을 요약으로 보여준다.
- 오류 또는 경고가 있는 행만 기본으로 표에 보여주며, 행 번호, 위스키명, 관련 필드, 메시지를 표시한다. 오류와 경고는 시각적으로 구분한다.
- 오류가 없는 경우에도 “검증만 완료되었으며 아직 등록되지 않았습니다”를 표시한다.
- 검증 버튼 옆에 업로드 버튼을 둔다. 오류가 없고 모든 행에 `normalized`가 있을 때만 업로드할 수 있다.
- 업로드 전에 등록 건수와 경고 건수를 확인하고, 반복 업로드 시 중복 등록될 수 있음을 알린다.
- 업로드 성공 후 등록 건수를 보여주고 같은 검증 결과의 업로드 버튼을 비활성화한다.
- 업로드 직전 서버 재검증이 실패하면 기존 Excel 행 정보에 새 오류·경고를 합쳐 검증 결과 표에 표시한다.

## State Matrix

| 상태               | 화면 처리                                                            |
| ------------------ | -------------------------------------------------------------------- |
| 초기               | 양식 다운로드와 파일 선택만 노출                                     |
| 파일 선택          | 파일명·크기와 검증 버튼 노출                                         |
| 검증 중            | 중복 요청을 막고 진행 상태 노출                                      |
| 검증 완료          | 요약 및 오류·경고 행 표 노출                                         |
| 검증 오류          | 서버 메시지와 재시도·다른 파일 선택 제공                             |
| 0행 파일           | 0건 검증 결과와 작성 안내 노출                                       |
| 업로드 가능        | 오류 0건, 1행 이상, 모든 행에 정규화 값이 있을 때 업로드 버튼 활성화 |
| 업로드 재검증 실패 | 서버의 행별 결과를 기존 검증 결과 표에 반영하고 업로드 비활성화      |
| 업로드 완료        | 등록 건수 표시, 같은 파일의 중복 업로드 방지                         |

## Acceptance Criteria

- [ ] ROOT_ADMIN이 위스키 정보 관리 메뉴에서 벌크 등록 화면으로 이동할 수 있다.
- [ ] 운영자가 서버 제공 양식을 다운로드할 수 있다.
- [ ] 운영자가 `.xlsx` 파일을 업로드해 실제 검증 API 결과를 확인할 수 있다.
- [ ] 오류·경고 행의 행 번호와 수정 사유를 확인할 수 있다.
- [ ] 화면 어디에서도 검증만으로 등록되었다고 오해하지 않는다.
- [ ] 오류가 없는 검증 결과를 확인 후 한 번에 등록할 수 있다.
- [ ] 경고만 있는 행은 확인 후 등록할 수 있다.
- [ ] 등록 재검증 실패 시 한 건도 저장되지 않고 같은 결과 표에서 오류를 확인할 수 있다.
- [ ] 등록 성공 후 같은 검증 결과를 다시 업로드할 수 없다.

## Delivery Slices

1. template/validate API 타입·서비스·TanStack Query mutation과 실제 요청 확인
2. 메뉴·라우트, 양식 다운로드, 파일 선택·검증 결과 요약
3. 행별 오류·경고 표와 focused Playwright 검증
4. 벌크 API 타입·서비스·훅, 업로드 확인·결과 UI와 재검증 실패 처리

## In Scope

- Excel 양식 다운로드와 업로드 검증 UI
- 검증 결과 요약 및 행별 피드백

## Out of Scope

- 기존 위스키의 일괄 수정·삭제
- 이미지 업로드
- 브라우저에서 Excel 셀을 직접 편집하는 기능

## Contract Verification

- 2026-09-08 공개 Admin OpenAPI와 백엔드 `main` 소스를 대조했다.
- 공개 계약과 서버 소스 모두 등록 요청을 JSON `rows`로 받고 저장 전에 전체를 재검증한다.
